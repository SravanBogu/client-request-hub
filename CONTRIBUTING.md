# Contributing

Thank you for contributing to Client Request Hub.

## Principles

- Use synthetic data only.
- Never submit employer, client, tenant, credential, or confidential material.
- Keep changes focused and documented.
- Follow the low-code-first, governed architecture approach.
- Include tests or validation evidence when code changes.
- Update relevant architecture, security, and deployment documentation.

## Branch naming

- `feature/<short-description>`
- `fix/<short-description>`
- `docs/<short-description>`
- `chore/<short-description>`

## Pull requests

Before opening a pull request:

- [ ] No secrets or sensitive data included
- [ ] Documentation updated
- [ ] Tests/checks completed where applicable
- [ ] Security, RBAC, DLP, ALM, and support implications considered
- [ ] Sample data remains synthetic
