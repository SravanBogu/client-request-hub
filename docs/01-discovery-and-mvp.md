# Discovery and MVP

## Problem statement

Request intake is fragmented across email, spreadsheets, calls, and
unconnected systems. This causes inconsistent routing, approval delays,
limited status visibility, missed SLAs, and weak auditability.

## Business outcomes

- Create a single intake experience.
- Standardize request categories and required information.
- Automate approval routing and notifications.
- Give coordinators a work queue and managers operational visibility.
- Measure volume, aging, approval time, completion time, and SLA performance.

## Personas

| Persona | Need |
|---|---|
| Requester | Submit and track a request |
| Approver | Review context and approve/reject quickly |
| Coordinator | Assign, fulfill, update, and close work |
| Operations Manager | Monitor backlog, SLA, trends, and bottlenecks |
| Platform Administrator | Govern security, environments, ALM, and support |

## MVP scope

- One request type or category.
- Request intake form.
- Request status lifecycle.
- Manager approval.
- Coordinator assignment.
- Teams/email notifications.
- Activity log.
- Basic reporting design.

## Out of scope for MVP

- Enterprise ERP/asset-system integration.
- Complex multi-stage approval matrices.
- External-user portal.
- Production AI assistant.
- Full SPFx command-center implementation.

## Success measures

- Request volume by category and location.
- Time from submission to approval.
- Time from approval to completion.
- SLA compliance percentage.
- Backlog aging.
- Rejection/rework rate.
- Adoption by user group.
